# 知识星图 · 重设计方案

> 对象：[src/components/OasisOrchard.tsx](../src/components/OasisOrchard.tsx) + [src/lib/constellation.ts](../src/lib/constellation.ts)
> 方法论沿用 Athena（unsw-mistral-hackathon-2026）的 `TRACK-C-DESIGN.md` / `TRACK-C-UI.md`：先定通道正交与不变量，再谈像素。
> 日期：2026-08-11

---

## 0. 三句话结论

1. **现在的问题首先是数据体量，不是算法。** 线上 5 篇文章 / 7 个标签 / 5 个单例标签 = 13 个节点。力导布局在这个规模下必然是散点，而它要到 50 篇以上才开始"涌现"结构。
2. **答案不是等文章变多，是换一种制图法。** 从「力导图」改成「天文星图」：先有确定性的极坐标框架（网格、节气刻度、螺旋年轮），再让星星落进去。真实星图上大部分墨水本来就是网格与黄道，星点反而稀疏——所以它在星很少时也不空。
3. **功能粗糙的解法是让星图开始说话。** 把 Athena 的 Hidden Signals 搬过来：星图不只展示已有的连接，还主动指出孤星、断链、桥星、冷却的星座、以及"这两篇很像但你从没链过"。**看的东西 → 给你留作业的东西。**

**关键：7 个标签团里 5 个是单例。**`buildGraph` 对每个标签一视同仁地建节点 + 画标签文字（[constellation.ts:149](../src/lib/constellation.ts:149)），于是屏幕上一半的"主题星云"其实各自只归纳了一篇文章——`#易经 1`、`#随笔 1`、`#网络流 1`、`#hackathon 1`、`#projects 1`。这是**结构性噪声**，不是数据不够造成的，文章涨到 100 篇后单例标签只会更多。

### 1.4 编码：数据模型里有四个字段，星图一个都没用

`BlogPost` 上现成的 `series` / `growth` / `updatedAt` / `status`（[useGarden.ts:18](../src/hooks/useGarden.ts:18)）在星图里全部不可见。

其中 **`series` 是最刺眼的一处**：这个组件叫 *The Constellation of Thought*，而合集——同一主题、有顺序、可命名的一串文章——恰恰就是天文学意义上的「星座连线」（asterism），却完全没画。`COMP3121` 那 3 篇现在是三个各不相干的点。

## 2. 设计命题

> **不要做一张力导图的截图，要做一张星图。**

从 Athena 那两份文档里可以直接搬过来三条：

- **通道正交**（`TRACK-C-DESIGN §6`）：四个视觉通道各自只编码一件事，永不重叠。星图目前只有两个半通道（颜色=分类、大小≈字数、透明度混合承担了"被筛掉"和"没被点亮"两种含义）。
- **不重排画布**（`D1`/`D2`）：一次交互毁掉布局就是毁掉整个演示。这里对应"点开文章不该让天空消失"。
- **面板永不为空**（`§2`）：空着的三分之一屏是最贵的浪费。星图现在右侧只有一列图例。

再加上星图学本身的六个要素——每一条都在"星很少"的时候仍然成立：

| 星图要素 | 在 Oasis 里是什么 | 为什么解决"简陋" |
| --- | --- | --- |
| 绝对坐标（赤经赤纬） | 极坐标框架：角=时间或主题，径=时间或向心度 | 位置有意义 → 可记忆、可预期、无需"重排" |
| 星座连线（asterism） | `series` 合集，按 `createdAt` 顺序连成折线并命名 | 5 篇文章立刻能画出 1 个真实星座 |
| 星等（magnitude） | 字数 + 入链数 + 共鸣数 的复合量 | 提供分级 → 支撑 LOD 标签显隐 |
| 坐标网格与黄道 | 节气刻度环 + 同心年轮 + 晷针 | **背景承担美学，星点承担信息**——这是天空不空的根本原因 |
| 星云与银河 | 由文章密度生成的弥散场 | 免费的纹理与深度 |
| 观测者位置 | 中心的头像 | 已有，保留 |

## 3. 布局：确定性极坐标框架 + 局部松弛

丢掉"全局力导 + 随机初值"，换成**先算框架、再局部收敛**。整体 O(n)，可预测，且不需要「✦ 重排星图」这个按钮（可以删掉——没有随机就没有重排的必要）。

### 3.1 两种投影，可切换

像地图有墨卡托和摩尔威德，星图给两种投影，用同一份数据。

**「历」投影（默认，N < 30 时唯一有意义的那个）**

```
θ = 2π · (dayOfYear(createdAt) / 365)        // 从立春起算，顺时针
r = R0 + RING · yearsAgo(createdAt)          // 一圈 = 一年，多年 → 阿基米德螺线
```

- 位置**永不改变**：`createdAt` 定死之后，这颗星的坐标是常量。加文章不会动到任何旧星，比现在的增量松弛更彻底。
- 外圈画 **24 节气刻度**（`lib/solarTerms.ts` 已有 `SOLAR_TERMS` / `currentSolarTerm`），当前节气那根高亮。
- 从核心指向"今天"的角度画一根缓慢转动的**晷针**。这是整个设计里我最想要的一笔：星图上有一根影子在走，站点是活的。
- 24 天的花园现在只是一段小弧——**诚实，且留出了生长的形状**。这比一把散点动人得多。

**「星座」投影（N ≥ 30 自动可用）**

```
社区检测 → 每个社区一个扇区，弧长 ∝ √size（不用 size，否则大社区吃掉整圈）
θ = 扇区内按向心度抖动
r = R_max · (1 - centrality)     // 越核心越靠内
```

- 社区检测用 **Label Propagation**：O(E)、约 25 行、零依赖，比 Louvain 简单得多且在这个量级效果相当。
- 扇区排序让"跨社区边最多的两个社区相邻"——社区数很小，贪心链式排序足够。
- N < 30 时**明说**：`星座识别将在第 30 颗星点亮`。宁可写出门槛，也不要在 5 个节点上跑社区检测然后展示一个滑稽的结果。

**两种投影之间的切换是这个页面的高光时刻**（Athena `TRACK-C-UI §0` 的 peak-and-end 原则）。极坐标下做 FLIP，900ms，按星等错峰（亮星先动）。看着自己的文章从日历重组成星座，是这个站点最值得被记住的 3 秒。

### 3.2 局部松弛

框架给完位置后，只跑 ~40 轮**约束松弛**：解重叠 + 让强关联的星互相靠拢，但 θ 限制在 ±Δ 扇区内、r 限制在 ±8% 内。确定性、快、且不会把语义位置搅乱。

`posCache` 保留，但用途从"防止重排"降级为"驱动转场动画的起点"——因为已经不会重排了。

## 4. 图谱构建：边的取舍

现在所有边一样重要（视觉上双链甚至最弱，`opacity: 0.2` 的虚线，[OasisOrchard.tsx:207](../src/components/OasisOrchard.tsx:207)），这是反的：**双链是作者亲手写下的联结，应该是最亮的那种边。**

### 4.1 标签按频次分三档

| 标签频次 | 处理 | 今天的数据 |
| --- | --- | --- |
| ≥ 4 篇 | 建星云 hub 节点，hub→post 星形 | 无 |
| 2–3 篇 | **不建节点**，文章之间直连（最多 3 条边） | `计算机`、`comp3121` |
| = 1 篇 | **不建节点**，只在星旁留一个 1px 刻痕，抽屉里才列出 | 其余 5 个 |

对今天的数据：节点 13 → 6，边 18 → 约 6。**屏幕上东西变少了，信息量反而上升**，因为剩下的每条边都真的意味着什么。这条规则同时解决了 A5（常用标签爆炸）。

### 4.2 四类边，四种画法

| 边 | 语义 | 画法 |
| --- | --- | --- |
| **合集 asterism** | 同一连载，有顺序 | 实线折线，按 `createdAt` 串起，合集专属色（`AURA` 按名 hash），**沿线画曲线标签写合集名** |
| **双链 wikilink** | 作者亲手写下的引用 | 最粗最亮的实线（现在是最暗的虚线，反了） |
| **共享标签** | 同一主题 | 细实线，透明度按标签 IDF 加权（罕见标签的共现更有信息量） |
| **潜在联结** | 算法猜的（见 §4.3） | 点线，**仅在专门模式或 hover 时出现**，永远视觉最弱，并明确标注为推测 |

hover 任意一条边要能说出**为什么**：「因为共享 `#comp3121`」/「因为《A》里写了 [[B]]」/「因为同属合集《COMP3121》」。可解释的边才是知识图谱，不可解释的边只是装饰。

### 4.3 潜在联结（Athena 的 Hidden Signals 移植）

Athena 用 `mistral-embed` 做跨团队语义连接、`find-contradictions` 挖矛盾。个人花园里的等价物是：**两篇你从没互链、也没共享标签，但其实在说同一件事的文章。**

- **P2 用 TF-IDF，不要一上来就上 embedding。** 中文分词用浏览器原生 `Intl.Segmenter('zh', {granularity:'word'})`——零依赖、零网络、零成本，在 N < 200 时余弦相似度足够找出真正的近邻。这也和 `useGarden` 的"云端失败静默回落本地"哲学一致：**不引入一个断网就废掉的核心功能**。
- **P3 再上 embedding**：Supabase 加一列 `embedding vector(1024)`，`updateSeed` 时异步写入，失败不影响保存。这时相似度质量会明显上一个台阶。
- 关键是**动作而不只是展示**：候选联结旁边给一个「建立双链」按钮，点击直接把 `[[对方标题]]` 追加进正文并 `updateSeed`。星图从此是写作的入口。

### 4.4 未种下的星位

`resolveWikiLinks` 已经把命中不了的 `[[标题]]` 渲染成 `wikilink-pending`（[wikilinks.ts:30](../src/lib/wikilinks.ts:30)）。把这个语义提升成**空间对象**：在引用它的那颗星附近，画一个虚线空心的星位，点击 → 直接打开写作器并预填标题。

真实星图上也标记疑似天体。这一笔同时做到三件事：填满天空、暴露断链、变成写作入口。

## 5. 视觉编码：八个通道，互不重叠

Athena `TRACK-C-DESIGN §6` 的规矩放大版。**每个通道只编码一件事。**

| 通道 | 编码 | 说明 |
| --- | --- | --- |
| 星核颜色 | **分类 type** | 保持不变，与博客/图例同源（`useCategories`） |
| 半径 + 亮度 | **星等** = f(字数, 入链数, 共鸣数) | 拉开到 4–16px，用 log 压缩长尾。星等同时决定 LOD 门限 |
| 衍射星芒 | **growth** | evergreen 四芒、growing 两道微芒、seedling 无芒 |
| 外环笔画 | **status** | draft 虚线空心环、unlisted 点划环（仅站主可见） |
| 色温 | **freshness**（距 `updatedAt` 多久） | 久未照料 → 偏冷蓝白；刚照料 → 偏暖。**用色温不用透明度**——Athena `§4` 的教训：褪色的东西在投影仪上等于不存在，信息要放在不损失对比度的通道上 |
| 不透明度 | **唯一含义：被筛选掉**（dim 到 20%） | 现在这个通道同时承担"没被点亮"和"被过滤"，要拆开 |
| 描边圆环（accent） | **唯一含义：当前选中** | |
| 外发光脉冲 | **唯一含义：近 7 天新增或更新** | |

两处双编码（`TRACK-C-UI §2.3` 的色盲/投影仪论证）：growth 是「大小 + 星芒」不只靠颜色，status 是「笔画样式 + 图例」不只靠颜色。

**衍射星芒是性价比最高的一笔**：真实照片里亮星才有十字芒，"evergreen = 最亮 = 有芒"语义天然，SVG 四行就能画。

### 5.1 LOD：星等门限决定标签显隐

经典星图规则：**只标注亮于当前星等门限的星。**

```
门限 = f(zoom)   // 缩到最小只标最亮的 5 颗 + 合集名；放到最大全部标注
```

这一条直接解决 B6（一片无名的点）——静止时就有 5–8 个标题在天上，而不是必须 hover 才知道自己在看什么。同时标签必须**反向缩放**（`transform: scale(1/view.scale)`）保持恒定屏幕尺寸，解决 B4。

## 6. 交互与信息架构

### 6.1 抽屉取代全屏弹窗（Athena D2 直接移植）

点一颗星：
1. 星图平移，让这颗星落到左侧可见区（`centerAt` 等价物，400ms）
2. 右侧抽屉滑入（220ms，`cubic-bezier(.22,1,.36,1)`）
3. **画布不重排、不卸载**

抽屉内容：标题 / 分类 / 星等 / freshness / 摘要 → Markdown 正文 → **邻域**（同合集的前后篇、双链出入、共享标签的姐妹星），每一项可点，点了就是在星图上换选中，天空始终在。

抽屉背景**不要 `backdrop-filter`**——在持续动画的画布上做实时模糊是每帧重绘，正是 `TRACK-C-UI §5.1` 记录过的坑。用不透明面板 + 左缘 32px 渐变出血。

### 6.2 抽屉永不为空：星象台

没有选中时，抽屉显示 **Observatory / 星象台**：

- 四个数字：**星数 · 星座数 · 最亮的星 · 最久未照料**
- 本月新星 ticker
- **星象观测（What the sky noticed）**——按严重度排序，每条都可点、可执行：

| 信号 | 触发条件 | 点击动作 |
| --- | --- | --- |
| 🕳 **孤星** | 无共享标签、无双链、无合集 | 高亮它们，提示"给它一个标签" |
| 🔗 **断链** | `[[标题]]` 指向不存在的文章 | **打开写作器并预填标题** |
| 🌉 **桥星** | 介数中心性 top-1，且是两个社区间的唯一通路 | 高亮那条通路 |
| ✨ **潜在联结** | 相似度 > 阈值但从无联结 | **一键写入 `[[双链]]`** |
| ❄️ **冷却的星座** | 某主题超过 N 天无新星 | 筛选到该主题 |
| 🌱 **待长成** | seedling 超过 30 天未 `updatedAt` | 打开编辑 |

这是把「功能粗糙」翻过来的关键一步：**星图从展示物变成会给你留作业的东西。**它也让 5 篇文章的星图立刻有内容可讲——今天的数据就能产出至少两条真信号（5 颗孤立标签的星、`Hackathon` 是只有 1 篇的合集）。

### 6.3 局部星图

社区共识很一致：全局图谱是给人看的，**局部图谱才是给人用的**（[pjordan 的 local graph 记录](https://pjordan.substack.com/p/a-pkm-revelation-obsidian-local-graphs)）。选中一颗星后给一个「只看邻域」开关：1–2 跳邻居保留，其余隐去并重新居中。这是全局图谱在 200 篇后退化成毛线球时唯一还成立的用法，现在就该建好。

### 6.4 其余

- **搜索**：`/` 聚焦，模糊匹配标题 → 相机飞到那颗星并点亮
- **键盘**：`/` 搜索 · `Esc` 关抽屉（现在完全没有）· `←/→` 在同一星座内前后翻 · `?` 图例 · `1/2` 切投影
- **URL 即状态**：`route.ts` 的 `ITEM_VIEWS` 加入 `orchard`，支持 `#/constellation/<slug>`，选中态可分享、可后退
- **指针锚定缩放**：缩放时补偿 `x/y` 使指针下的点不动（修 B2）
- **双指捏合**：改成多指针 Map，`touch-none` 保留但自己实现捏合（修 B3）
- **平移边界**：夹到内容包围盒 ±50%（修 B5）
- **Tab 顺序按星等降序**，不按 DOM 顺序——最亮的星先被访问到

## 7. 性能与可访问性

**现在的瓶颈不在布局，在 hover。** `setHoverPostId` → `lit` 重算（遍历全部边）→ 整棵树重渲染 N 个 `motion.button`。5 篇无感，200 篇会掉帧。

- **P1**：星层拆成 `memo` 子组件，props 只传 `isLit` / `isDim` 布尔，切断"一次 hover 全树重渲染"。
- **N > 200 才转 Canvas**：背景层（星尘、密度场、网格、连线）走 Canvas，DOM 只保留"有标签且可交互"的星，命中测试用 quadtree。给出明确阈值，而不是"以后再说"。
- 极坐标框架是 O(n)，局部松弛只剩 40 轮 → 首屏布局预算 < 100ms @ 300 篇（现有测试标定 600 篇全量 270ms，新方案应更快）。测试文件 [constellation.test.ts](../src/lib/constellation.test.ts) 的耗时上界断言全部保留，稳定性断言改写为"位置是 `createdAt` 的纯函数"这个更强的不变量。

可访问性（`TRACK-C-UI §8`，成本极低）：
- `Esc` 关抽屉、focus 进入抽屉标题、关闭后焦点回到那颗星
- `aria-live` 播报选中的星
- 颜色之外必有第二通道（星芒 / 笔画 / 图例）
- `prefers-reduced-motion`：晷针停走、投影切换直接切、呼吸动画关闭（现有 `reduceMotion` 判断保留）

## 8. 分期

| 期 | 内容 | 判据 |
| --- | --- | --- |
| **P0** | 极坐标框架 + 节气刻度 + 晷针 + 密度场背景；单例标签不再建节点；`series` 画成星座连线；星等重标定 + LOD 标签；抽屉取代全屏弹窗；指针锚定缩放 + 捏合 + 边界；删掉「✦ 重排」按钮 | **5 篇文章时截图不空，且一眼能读出三件事** |
| **P1** | 星象台面板 + 星象观测（孤星 / 断链 / 桥星 / 冷却 / 待长成）；未种下的星位；搜索 + 键盘 + URL 状态；八通道编码补齐（星芒 / 色温 / status 环）；hover 性能下沉 | 星象观测能给出至少一条可执行建议，点击直接进写作 |
| **P2** | TF-IDF 潜在联结 + 一键建链；社区检测 + 「星座」投影 + FLIP 转场；局部星图 | 两种投影切换是这个页面最值得录屏的 3 秒 |
| **P3** | Supabase pgvector embedding 升级相似度；时间轴 scrubber（拖动看星空逐颗点亮）；N>200 时的 Canvas 渲染层 | — |

P0 就能把"简陋"这个词摘掉，因为它把美学负担从"星点数量"转移到了"制图背景"。

## 9. 不做什么

- **不做 3D 星空。** three.js 的粒子星海好看，但导航更差、移动端性能更差、文本更难读。这是 `TRACK-C-UI §1` 那条"generic dark-SaaS 反模式"的星图版本。
- **不把 embedding 放进 P0。** 它会让一个核心功能依赖网络与 API key，直接违背 `useGarden` 全套的"云端失败静默回落"哲学。TF-IDF 先上，够用了再换。
- **不在 N < 30 时跑社区检测。** 写出解锁门槛，比展示一个荒唐的分组诚实。
- **不给星等/freshness 用透明度。** 那是"被筛掉"这一个含义的专属通道。

## 10. 验收标准

1. 只有 5 篇文章时，星图截图里能读出三件事：现在是哪个节气、`COMP3121` 是一串连着的、哪颗是 evergreen。
2. 新种一篇文章，它的位置**可以被预言**（同一天写的文章落在同一角度），且没有任何旧星移动。
3. 点开一颗星，天空不消失、不重排：星图平移 + 抽屉滑入，一个手势读完。
4. 每一条连线 hover 都能说出它为什么存在。
5. 星象观测至少给出一条真实、可执行的建议，点击直达写作或建链。
6. 300 篇时首屏布局 < 100ms，hover 不掉帧。
7. 键盘全可达，`Esc` 可退，`prefers-reduced-motion` 生效，移动端可捏合缩放。
