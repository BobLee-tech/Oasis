## T1 · 底部安全区：统一真值来源

### 为什么

`--oasis-bottom-safe-space` 目前算的是 `4rem + 0.75rem + safe` = 76px。这在移动端正确（Dock `bottom-[safe+0.75rem]`，`p-2` + `h-12` = 64px）。但 **md+ 上 Dock 是 `md:bottom-8`（32px）**，实占 `32 + 64 = 96px`。实测：视口高 998px 时 Dock 顶边在 `y = 900`。token 少算约 22px，而 `src/components/OasisOrchard.tsx:887` 把这个 token 当硬边界用。

## T3 · 转场闸门：切换场所时冻结氛围层

### 为什么

切换场所时叠着三样东西同时工作：

1. `AnimatePresence mode="wait"` —— 旧场所淡出 0.5s，**淡完之后**才挂载新场所，于是「懒加载 chunk 求值 + 首帧渲染」这个不可中断的长任务精确砸在入场动画第一帧。
2. 正在做 opacity 动画的子树里有 `src/components/OasisResonance.tsx:61` 的 `AmbientGlow`：115% 视口大小的 `blur-[100px] dark:blur-[130px]` + `mix-blend-multiply / dark:mix-blend-screen`；以及第 35 行 `DiscHalo` 的 `blur-3xl`。opacity 动画本该是合成器上改一个 alpha，被这两层拖回每帧重画全屏高斯。`mix-blend-*` 还会让整棵子树掉出快速合成路径。
3. 同时还有 `RippleBloom`（3 圈 + 一个 360px `blur(10px)` 径向光）、`ClickRipples`、桌面端常驻的 `NoiseOverlay`（全屏 `feTurbulence`）。

本任务只做**代价最小、收益最大**的那一步：转场期间把氛围层整体关掉。

### 改动

#### 3a. `src/App.tsx`

## T4 · 阅读舱常驻出口

### 为什么

关闭 ✕ 在 `src/components/OasisGallery.tsx:1776`，位于正文流内（`flex justify-end … mb-12`），**随内容一起滚走**。阅读舱里唯一常驻的浮层是右下墨环（回顶）和左侧目录耙痕 —— 唯独「出口」不固定。ESC 能关但界面零提示。

违反 Nielsen 启发式 #3「用户控制与自由」：进入全屏模式必须始终有可见的紧急出口。

**位置分叉的理由**：桌面左侧被目录耙痕占用（`fixed left-7 top-1/2`），所以 ✕ 放右上；移动端右上已有目录钮（`lg:hidden fixed top-5 right-5`），所以 ✕ 放左上 —— 那也正是 iOS 的返回位。

**尺寸恒定 40px，不做「滚动后收缩」的宽度动画** —— 那是布局动画，违反 §0.1。

### 改动

#### 4a. `src/components/OasisReader.tsx`

## T21 · Miku 贴图降采样（先做，T6 的前提）

### 为什么

**实测**：`public/live2d/miku/miku_sample_t04.2048/texture_00.png` 是 **2048×2048**，
文件 4.2MB，上传 GPU 后按 RGBA8 计算占 **16.0MB 显存**。

而舞台最大只有 152×236 CSS px（`profileFor()` 的桌面档），`resolution` 上限是 2，
即最大渲染尺寸 **304×472 物理像素**。1024² 的贴图在这个尺寸下仍然是 2 倍超采样，
视觉上不可能有差别 —— 2048² 纯属浪费。

降到 1024²：**显存 16MB → 4MB，下载 4.2MB → 约 1.2MB**（转 WebP 后约 400KB）。
这也顺便修掉一个从没被注意到的问题：4.2MB 的贴图会让首次展开 Miku 在慢网络下等很久。

### 改动

#### 21a. 新建 `scripts/downscale-live2d-texture.mjs`

```js
// Live2D 贴图降采样：2048² → 1024²，并转 WebP。
//
// 舞台最大 152×236 CSS px，resolution 上限 2，即最大渲染 304×472 物理像素 ——
// 1024² 仍是 2 倍超采样，视觉上不可能有差别，而显存从 16MB 降到 4MB、
// 下载从 4.2MB 降到约 400KB。贴图坐标在 moc3 里是归一化的，换分辨率不需要动模型。
//
// ⚠️ 缩放必须正确处理预乘 alpha，否则半透明边缘（发梢、裙摆）会渗出黑边。
//    sharp 默认在 resize 时预乘，这里显式写出来以免将来改配置时踩坑。
```

- 输入：`public/live2d/miku/miku_sample_t04.2048/texture_00.png`
- 输出：`public/live2d/miku/miku_sample_t04.1024/texture_00.webp`
- 参数：`sharp(src).resize(1024, 1024, { kernel: 'lanczos3', fit: 'fill' }).webp({ quality: 92, alphaQuality: 100, effort: 6 })`
- 保留原 2048 目录不删（作为母版，`.gitignore` 里不排除它）

在 `package.json` 增加 `"live2d:texture": "node scripts/downscale-live2d-texture.mjs"`，
在 `scripts/README.md` 登记。

#### 21b. 改 `public/live2d/miku/miku_sample_t04.model3.json`

```json

      "miku_sample_t04.1024/texture_00.webp"
    ],
```

### 验收

- 展开 Miku，肉眼对比降采样前后截图：发梢、裙摆、耳机细节无可见差异，边缘无黑边渗出。

## T7 · Miku 泊位不再瞬移

### 为什么

`measureBerths` 一律用 `x.set()` / `y.set()`（瞬时无动画），而它在 `view` 变化、`onReady`、每次 resize 时都会跑。切换场所时如果 `[data-miku-avoid]` 的避让结果换了泊位，她就是「闪」过去的 —— 这正是「闪回」的观感来源。

### 改动

**文件：`src/components/OasisMiku/index.tsx`**

新增一个 ref 跟踪是否已定过位（`positioned` 是 state，在 `measureBerths` 内读不到最新值）：

```tsx

```

`measureBerths` 内 `x.set(target.x); y.set(target.y);` 替换为：

```tsx
      // 首次定位用 set：那一刻她还是透明的（opacity 由 positioned 控制），瞬移看不见。
      // 之后一律走 spring —— 切换场所导致避让换泊位时，她是「游」过去的，不是「闪」过去的。
      const settle = (mv: MotionValue<number>, to: number) => {
        if (!positionedRef.current) { mv.set(to); return; }
        animate(mv, to, prefersReducedMotion
          ? { type: 'tween' as const, duration: 0.01 }
          : { type: 'spring' as const, stiffness: 300, damping: 32, mass: 0.9 });
      };
      settle(x, target.x);
      settle(y, target.y);
```

`setPositioned(true)` 之后同步 `positionedRef.current = true;`。
`collapse()` 与 `expand()` 里 `setPositioned(false)` 处同步 `positionedRef.current = false;`。

## T8 · Miku resize 不再逐事件重渲染

### 为什么

`viewportWidth` 是每个 resize 事件都 `setState` 的（无节流），`measureBerths` 依赖它；而 `measureBerths` 内部又 `setBerth`，改变自己的依赖身份 → effect 反复解绑重绑 resize 监听。拖窗口期间整棵 Miku 子树逐事件重渲染。

```tsx
  // 而 measureBerths 的身份跟着变，effect 又反复解绑重绑监听。
  // 同档位返回同一引用 → React 直接跳过渲染。
  const [profile, setProfile] = useState(() => profileFor(window.innerWidth));
```

## T12 · 眨眼调度器

### 为什么

`src/components/OasisMiku/Live2DStage.tsx` 里 `(model.internalModel as Cubism4InternalModel).eyeBlink = undefined;` 关掉了自动眨眼，改由动作曲线负责。代价是**眨眼节奏被锁死在 2.3–2.4s 的循环上**。

完美周期正是人眼判定「机械」最敏感的信号 —— 这和 `src/components/OasisMiku/brain/rhythmEngine.ts` 里花大力气避免的是同一件事，只是在眨眼上又回来了。

官方 `CubismEyeBlink` 的做法是「设定间隔，实际取 0~2× 的均匀随机」（见 https://docs.live2d.com/en/cubism-sdk-manual/autoeyeblink/ ），但均匀分布会产生大量过短的间隔，看着像抽搐。

### 改动

**新建 `src/components/OasisMiku/brain/blink.ts`**

```ts
// 👁 眨眼调度器。
//
// 动作曲线里自带的眨眼把节奏锁死在 2.3~2.4s 的循环上，而完美周期是人眼判定「机械」
// 最敏感的信号 —— 这和 rhythmEngine 里花大力气避免的是同一件事。
//
// 官方 CubismEyeBlink 的做法是「设定间隔，实际取 0~2× 的均匀随机」，但均匀分布会产生
// 大量过短的间隔，看着像抽搐。这里换成对数正态：中位数 3.4s（真人 15~20 次/分），
// 长尾偶尔给出 8~10s 的凝视；再加 12% 概率的双次眨眼 —— 那是真人在思考或切换注意力
// 时的标志性动作，也是「她在想事情」这个印象的主要来源。
const CLOSING_S = 0.09;   // 闭合
const CLOSED_S = 0.045;   // 保持
const OPENING_S = 0.16;   // 张开（比闭合慢，真人如此）
const MEDIAN_S = 3.4;
const SIGMA = 0.55;
const DOUBLE_BLINK_P = 0.12;

export class BlinkEngine {
  private wait = 1.2;
  private phase: 'idle' | 'closing' | 'closed' | 'opening' = 'idle';
  private t = 0;
  private queued = 0;

  private nextWait(): number {
    // Box–Muller → 标准正态 → 对数正态
    const u = Math.max(1e-6, Math.random());
    const v = Math.random();
    const g = Math.sqrt(-2 * Math.log(u)) * Math.cos(2 * Math.PI * v);
    return MEDIAN_S * Math.exp(g * SIGMA);
  }

  /** @returns 0（闭）… 1（睁），写进 ParamEyeLOpen / ParamEyeROpen */
  update(dtSec: number): number {
    this.t += dtSec;
    switch (this.phase) {
      case 'idle':
        if (this.t >= this.wait) {
          this.phase = 'closing';
          this.t = 0;
          if (this.queued === 0 && Math.random() < DOUBLE_BLINK_P) this.queued = 1;
        }
        return 1;
      case 'closing':
        if (this.t >= CLOSING_S) { this.phase = 'closed'; this.t = 0; return 0; }
        return 1 - this.t / CLOSING_S;
      case 'closed':
        if (this.t >= CLOSED_S) { this.phase = 'opening'; this.t = 0; }
        return 0;
      case 'opening':
        if (this.t >= OPENING_S) {
          this.phase = 'idle';
          this.t = 0;
          if (this.queued > 0) { this.queued -= 1; this.wait = 0.14; }
          else this.wait = this.nextWait();
          return 1;
        }
        return this.t / OPENING_S;
    }
  }
}
```


```ts
const VOWEL_OF: Record<string, 'a' | 'i' | 'u' | 'e' | 'o'> = {

const FORM_OF = { a: 0.05, i: 0.85, u: -0.75, e: 0.45, o: -0.45 } as const;

export class LipSync {
  private open = 0;
  private form = 0;

  /**
   * @param lyric     当前活跃歌词行，间奏/无歌词时为 null
   * @param midEnergy getEnergy().mid，兜底用，同时调制音拍开合的深浅
   * @param own       是不是她自己的歌。不是的话只跟着哼 —— 不该抢别人的主唱
   */
  update(dtSec: number, lyric: ActiveLyric | null, midEnergy: number, own: boolean) {
    let target = 0;
    let formTarget = 0;

    if (lyric?.beats.length) {
      const p = lyric.progress();
      const beat = lyric.beats.find(b => p >= b.from && p < b.to);
      if (beat) {
        // 一个音拍内的轮廓：快开、慢合，收在一个「字」上，而不是方波。
        // 指数 0.7 让波峰略平 —— 真人一个音节的口型是有保持段的。
        const t = (p - beat.from) / Math.max(1e-4, beat.to - beat.from);
        target = Math.sin(Math.PI * Math.min(1, t * 1.12)) ** 0.7;
        // 深浅由实际音量调制：轻声的字不该和爆发的高音张一样大的嘴
        target *= 0.45 + midEnergy * 0.55;
        const v = VOWEL_OF[beat.text[0]];
        formTarget = v ? FORM_OF[v] : 0.1;
      }
      // 找不到音拍 = 落在字与字之间的缝里，自然闭合，什么都不做
    } else {
      target = midEnergy * 0.85;
    }

    if (!own) { target *= 0.3; formTarget *= 0.4; }

    // 张口比闭口快 —— 下颌下落靠重力、回位靠肌肉，真人也是这个不对称
    const tau = target > this.open ? 0.045 : 0.11;
    this.open += (target - this.open) * (1 - Math.exp(-dtSec / tau));
    this.form += (formTarget - this.form) * (1 - Math.exp(-dtSec / 0.13));
    return { open: this.open, form: this.form };
  }
}
```

## T18 · 数据层：密度分箱与几何工具

### 改动

**文件：`src/lib/constellation.ts`**，追加导出：

```ts
/** 按节气分箱的写作密度：24 个箱，值 = 落在该节气区间内的文章数。
 *
 *  这是年轮盘的主角图层。8 颗星撑不起一张星图 —— 角度编码（= 写作日期）在圆周上
 *  稀到读不出季节，连线也少到形不成星座。但 8 篇文章落进 24 个箱里，
 *  「立秋前后连写了 4 篇」这件事一眼就成立，而且文章越多它只会越好看，
 *  不会像连线那样越多越乱。 */
export interface DensityBin { index: number; a0: number; a1: number; count: number }
export const densityByTerm = (posts: Pick<BlogPost, 'createdAt'>[]): DensityBin[] => {
  const bins: DensityBin[] = Array.from({ length: 24 }, (_, i) => ({
    index: i,
    a0: -Math.PI / 2 + (i / 24) * TAU,
    a1: -Math.PI / 2 + ((i + 1) / 24) * TAU,
    count: 0,
  }));
  for (const p of posts) {
    const f = solarYearPosition(p.createdAt).fraction;
    bins[Math.min(23, Math.floor(f * 24))].count += 1;
  }
  return bins;
};

/** 极坐标环扇形 path。密度弧、节气环高亮段、分类带分隔都用它，
 *  避免三处各写一遍角度换算。 */
export const annularSector = (a0: number, a1: number, r0: number, r1: number): string => {
  const pt = (a: number, r: number) =>
    `${(CENTER.x + Math.cos(a) * r).toFixed(2)} ${(CENTER.y + Math.sin(a) * r).toFixed(2)}`;
  const large = a1 - a0 > Math.PI ? 1 : 0;
  return `M${pt(a0, r0)}A${r0} ${r0} 0 ${large} 1 ${pt(a1, r0)}`
       + `L${pt(a1, r1)}A${r1} ${r1} 0 ${large} 0 ${pt(a0, r1)}Z`;
};

/** 圆弧 path（无填充），供 textPath 沿弧排字。 */
export const arcPath = (r: number, a0: number, a1: number): string => {
  const pt = (a: number) =>
    `${(CENTER.x + Math.cos(a) * r).toFixed(2)} ${(CENTER.y + Math.sin(a) * r).toFixed(2)}`;
  const large = a1 - a0 > Math.PI ? 1 : 0;
  return `M${pt(a0)}A${r} ${r} 0 ${large} 1 ${pt(a1)}`;
};

/** 一维松弛：把同侧标注按 y 排序，冲突时向两端推开，并钳在 [lo, hi] 内。
 *
 *  年轮盘里名字是主要内容不是装饰，所以不能沿用「八个候选位都放不下就不写」的策略。
 *  名字全部移到环外之后，冲突退化成一维问题，标准松弛就能做到容量内一个不漏。
 *  超出容量的部分由调用方按星等取舍（见 T19 的降级策略），不由这里决定。 */
export const relaxColumn = <T extends { y: number }>(
  items: T[], minGap: number, lo: number, hi: number,
): T[] => {
  const sorted = [...items].sort((a, b) => a.y - b.y);
  for (let pass = 0; pass < 48; pass++) {
    let moved = false;
    for (let i = 1; i < sorted.length; i++) {
      const d = sorted[i].y - sorted[i - 1].y;
      if (d < minGap) {
        const push = (minGap - d) / 2;
        sorted[i - 1].y -= push;
        sorted[i].y += push;
        moved = true;
      }
    }
    if (sorted.length) {
      sorted[0].y = Math.max(sorted[0].y, lo);
      sorted[sorted.length - 1].y = Math.min(sorted[sorted.length - 1].y, hi);
    }
    if (!moved) break;
  }
  return sorted;
};
```

> ⚠️ **不要新增 `skyMode` / `SKY_DENSE_MIN`**。早期草案里有这两个导出，已随「不做双态」的定案取消。

### 新增测试

- `relaxColumn`：输出长度不变；输出按 y 升序；全部落在 `[lo, hi]`；当 `hi - lo ≥ (n-1) * minGap` 时相邻间距均 ≥ `minGap`。

## T23 · 惰性释放

### 为什么

T6 让舞台常驻，收放变成纯合成器动画。但「收起后再也不打开」这个最常见的情况下，
4MB 显存 + 一个 WebGL 上下文会一直挂着到标签页关闭。

折中：**收起 = 停摆（秒级恢复）；收起超过 5 分钟 = 真正释放**。
5 分钟之后用户大概率不会马上再开，即使再开，付一次加载成本也可以接受。
这样既拿到了「反复收放丝滑」，又不会为一个用户已经放弃的挂件长期占着资源。

### 改动

**文件：`src/components/OasisMiku/index.tsx`**

```tsx
  // ⏳ 惰性释放：收起只是停摆（T6），但连续收起超过 5 分钟就真正销毁。
  //    「反复收放要丝滑」和「不用了就别占着显存」这两件事的交点。
  //    重新展开时若已释放，付一次加载成本 —— 那时用户已经离开她 5 分钟以上，
  //    对一次加载的容忍度和首次展开是一样的。
  const RELEASE_AFTER_MS = 5 * 60 * 1000;
  useEffect(() => {
    if (expanded || !mounted) return;
    const timer = window.setTimeout(() => setMounted(false), RELEASE_AFTER_MS);
    return () => window.clearTimeout(timer);
  }, [expanded, mounted]);
```

`setMounted(false)` 会卸载 `Live2DStage`，其既有 cleanup 完成销毁 —— **不需要新增销毁逻辑**。

同时把 `positionedRef.current = false` 与 `setPositioned(false)` 一并复位，
下次展开走「首次定位用 set」的路径（T7），不会出现从旧坐标弹到新坐标。

### 验收

- 收起后立即再展开（< 5 分钟）：`data-ready` 立刻为 `"true"`，无 LOADING…
- 收起后等待 5 分钟：`document.querySelectorAll('canvas').length` 减 1，
  Chrome 任务管理器里该标签页的 GPU 内存下降约 4MB。
- 释放后再展开：正常重新加载，位置正确，不出现从旧坐标弹出的动画。
