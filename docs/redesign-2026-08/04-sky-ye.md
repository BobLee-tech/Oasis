## 1. 为什么是重做，不是精修

### 1.1 实测（1280×800，8 篇，处暑）

| 项 | 实测 | 判断 |
|---|---|---|
| 内容占屏 | 21.5%，偏右下 | 主语只占五分之一 |
| 骨架对比度 | 2.13 : 1 | 低于 WCAG 1.4.11 的 3:1 |
| 星名对比度 | 12.48 : 1 | 与骨架差 5.9 倍，中间全空 |
| 带名字体 | `ui-sans-serif` | 全 SVG 唯一的无衬线，是漏字体不是风格 |
| 年轮填充率 | 2 / 12 月，**8 / 72 格** | 十分之八的刻度量的是没发生的事 |
| 分类带 | 3 条，最少的 1 篇 | 五档光谱只有三个停点 |
| 关系线 | 合集 1 条 | 「星座」实际只有一个 |
| L0 上屏的字 | 8 星名 + 8 条 150px 引线 | 名字比图重 |

### 1.2 两条结论

1. **六套编码，八个数据点。** 24×3 = 72 个格子填了 8 个。读者看到的不是「天很空」，
   是「这张表没填完」——量尺画得越工整，空就越像失败。
2. **最贵的两个通道花在最便宜的两个事实上。** 角度=日期、半径=分类，这两件事博客列表
   已经用一行日期和一枚 chip 说清楚了。星图因此没有职位。

第三条不写进表格但同样致命：**它不属于这个站。** `#/garden` 是暖调编辑排版，
星图是一张冷的发丝线科学插图。像技术图被贴进了诗集。

## 2. 五条原则（改动之前先过一遍）

1. **稀疏时是一幅画，稠密时才是一台仪器。** n=8 要好看，n=800 要仍然真。
   任何「等文章多了就好看了」的设计，对未来两年的这个站都是错的。
2. **贵的通道留给文字说不出的事。** 位置给关系，大小给分量；日期与分类交给图层和筛选。
3. **空白由边界定义，不由格子丈量。** 撤掉刻度网格，加上版心刻边。
4. **图形从数据长出来。** 连线就是合集次序。**绝不为了好看补装饰性的假星**——
   空处交给材质与排版，不交给假数据。
5. **底图只有一张，尺可以有很多把。** 时间尺、待照料都是可开关的图层。

> 关于旧文件头第 5 条「年轮盘是唯一底图，不做双态」：那条规矩当初是为了避免维护两套构图。
> 本方案只有一张构图（版面），内容随规模自然增减，叠加层不改构图。顾虑不成立，不是被忽略。

## 4. 数据层：落座

### 4.1 一条规矩：出生时择邻，此后终生不迁

按 `createdAt` 顺序依次落座，每一步**只看已经落好的星，从不回头改**。
所有布局智力都花在「这颗星生在哪」，落下之后再不动它。

| 情形 | 落法 |
|---|---|
| 进已有合集 | 从该合集最后一颗星**沿它的走向续一步**（带种子扰动），链自己往前长 |
| 开了新合集 | 在 137.5° 黄金角螺线上取下一块领地，半径 `TERR × √(k+.55) × (.74 + seeded(key)×.82)` |
| 散星 | 与已有群共标签就落在它旁边（半径 74–126），否则也上螺线 |
| 冲突 | **只往外推，永不换位**，直到间距 ≥ `MIN_SEP` |

常量：`MIN_SEP = 34`、`STEP = 58`、`TERR = 168`、`GOLD = 2.39996`、`SQUASH = .72`（天压扁一点，因为版心是横的）。

### 4.2 两个白送的结果

- **恒定星密度。** 领地半径 ∝ √k ⇒ 面积 ∝ 篇数。天不会变挤，只会变大，
  相机的 fit 倍率把增长吸收掉。
- **天心是最早的兴趣，天边是新开的坑。** 螺线由内向外发，这条读法是算法的副产品，
  不是画上去的——旧版那套「内圈暖星外圈蓝星」想表达的正是它。

### 4.3 实测

| n | 8 | 24 | 60 | 160 |
|---|---|---|---|---|
| 星密度 / 单位 | 1.87 | 2.71 | 1.42 | 1.21 |
| 星座数 | 1 | 4 | 13 | 24 |
| fit 倍率 | 1.04 | 0.82 | 0.60 | 0.36 |
| **最初八颗的位移** | **0.00** | **0.00** | **0.00** | **0.00** |

位移恒为 0 不是调出来的，是「只往后排」这件事的必然。

### 4.4 版心

`版心 = 所有星的包围盒 + pad 88`，下限 `780 × 526`，长宽比锁死。
星在长，版心跟着长，**老星一个都不动**。

### 4.5 测试怎么改

`src/lib/constellation.test.ts` 那两条不变量**都仍然成立**，但断言的构造方式变了：

- 「新增文章不移动任何旧星」——照旧，而且现在更强：追加任意条数、任意合集归属都不移动。
- 「任意两星间距 ≥ MIN_SEP」——照旧，由 `far()` 的外推循环保证。
- **新增一条**：`layout(posts.slice(0,k))` 的结果必须是 `layout(posts)` 前 k 项的前缀
  （落座是纯追加的）。这条能一次性守住上面两条的根。

## 5. 视觉

### 5.1 星体是四层，不是一个圆

| 层 | 一等 | 二等 | 三等 | 四等 | 五等 |
|---|---|---|---|---|---|
| 核 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 内晕（紧、白） | – | – | ✓ | ✓ | ✓ |
| 外晕（大、极淡） | – | – | – | ✓ | ✓ |
| 芒（四角尖 + 十字丝） | – | – | – | – | ✓ |

- 屏幕半径 `RPX = [2.4, 2.9, 3.6, 4.6, 6.4]`（最亮与最暗差约 7 倍面积）
- 外晕浓度 `HALO_O = [0, 0, 0, .2, .46]`——**只有最亮两档发光**。
  全场一起发光就没有远近，那是「一片肉球」的成因。
- **色相住在外晕上，核几乎不显色。** 亮星在真实照片里核已过曝成白，颜色都在光晕里。
  所以核的兑比按星等**反着走**：五等只兑 26% 分类色，一等兑 78%。
- 芒的形：内半径 `.15` 的四角星，再大成菱形、再小成十字线。
  ```
  M0,-1C.06,-.34 .34,-.06 1,0C.34,.06 .06,.34 0,1C-.06,.34 -.34,.06 -1,0C-.34,-.06 -.06,-.34 0,-1Z
  ```
  用 CSS `transform: scale(calc(var(--kk) / var(--s)))` 锁屏幕尺寸，不进每帧 JS。

**星等 = 篇幅，一档，不可切。** 门限 `[7, 12, 18, 25]` 分钟。
门限必须贴着真实数据定——现有最长的一篇 25 分钟，五等门限就得 ≤25，
否则最亮档和芒**永远不会出现**（原型里踩过：门限设 40，整张图一片平）。

### 5.2 昼夜：夜是星野，昼是水墨

几何、构图、注记两态完全共用，**只换光与墨**。

| | 夜 | 昼 |
|---|---|---|
| 天色 | `#11242C → #081219` 径向 | `#F4EEE0 → #FCFAF4`，宣纸帘纹 |
| 星 | 核近白（L .90–.99），三等起发光 | **墨分五色**：清 → 焦，`INK_DK = [56%, 66%, 78%, 90%, 100%]` 兑进纸色 |
| 星晕 | 冷白光晕 `--halo:1` | **墨晕**（洇开），`BLEED_O = [.30, .36, .44, .54, .66]`，半径 `R × 2.9` |
| 芒 | 有 | 无（纸上最亮的星就是最大的点，这是刻本的规矩） |
| 版框 | 双线，外 `.22` | **单道乌丝栏 `.42`**，内框线隐去（双细线是工程图的语气） |
| 闲章 | 樱粉 `#F2A9BD` | **朱砂 `#B5443C`** |
| 星尘 | 冷白/中性/暖白三色 | 墨点，`--dust: .2` |
| 银河 | `--galaxy: .26` | `.09`——白天这道是**淡墨渲染**，一笔带过 |

白天为什么不能沿用夜里的做法：**五档明度差会让淡墨小星在纸上直接消失，彩墨还会糊成褐点。**
墨色深浅 + 大小一起说，才分得出轻重。

### 5.3 星尘与银河：材质，不是数据

60 篇文章就是 60 个点，60 个点无论怎么调都不像一片星空。所以星尘归到**材质**这一类，
和纸纹同一个身份——它是「这张图印在什么上」，不是对内容的声称。

三条硬约束，保证它绝不会被误读成文章：

1. 半径上限 **0.95px**，恒小于最暗的数据星（2.4px）——层级不许倒挂
2. 没有名字、没有连线、**不参与拾取**
3. 数量跟版心面积走（`area / 1100`），与篇数无关

亮度走幂律 `(.035 + seed^3.4 × .72) × (.34 + band × .95)`：绝大多数几乎不存在，少数看得清。
平均分布是噪点，幂律才是星空。银河是一条 −26° 的高斯衰减带，带外抽稀（`keep = .06 + band × .8`），
于是天有疏处有密处。

**让路**：每颗数据星周围 26 单位、款框外扩 14 单位内不落尘。重要的东西站在干净的地方。

### 5.4 版面

- **刻边 + 四角角记**：空白由边界定义。
- **款识**（左上或左下，挑较空的那角）：`星野` / 干支·节气·花园第几日 / N 星 · N 集 · N 散。
  下接一道细线，再接**图例**——星等阶、连线含义、三个分类的色。
  图例用的是和图上**完全同一支笔**（共用 `starGlyph()`），所以它不会说谎。
- **款框**：刻本上款识占的是一块「留出来的空」。有了它，款识落在哪个角都读得清。
- **闲章** 落在款识的对角，**永远躲开右下角**——那儿是抽屉的地盘。

### 5.5 星链

转角 **±58°**，22% 概率来一个 1.5 倍的硬肘；步长在 **0.55–1.7 倍**之间跳。
等步长等转角画出来是一条蚯蚓，不是仙后座。

线的墨度分三档：全图 `o3` → 放大 1.5× 后 `o4` → 点亮 `o5`。

## 6. 注记

### 6.1 落名的资格（不是配额）

① 全图最亮的那颗　② 某个分类的**独苗**（它一个人代表一条带）　③ 星座名（另画）

n=8 落三处星名；n=60 落**一处**——分类都不再有独苗，资格自动消失，
地图的索引改由星座名承担。**这条规则自己会缩。**

### 6.2 星名：八方位择位

制图学的老规矩，优先级：**右上 → 左上 → 右下 → 左下 → 上 → 下 → 右 → 左**。
第一个不撞星盘、不撞别的字、不出版心的位置就是它的位置。

分两轮落：

- **第一轮**：能同时出现在 L0 的（常驻星名 + 星座名），全局互不重叠
- **第二轮**：各合集成员，只跟第一轮和同集兄弟避让——因为任何时刻只有一个合集是亮的

八个位置全被占：贴回星的右上。**宁可挨着，也不飞出去拉 150px 引线**——
那正是旧版「几行黑色诗句浮在白纸上」的由来。

### 6.3 星座名

- 全图只写**最大的五个**，放大 1.5× 补一倍，2.6× 再补两倍
- 在自己那一群下方往下找空位，二十步找不到就**自己收起来**——宁可少写一个名字，也不叠字

### 6.4 极限星等

星是恒定屏幕尺寸的，一屏站得下多少颗有物理上限。全天图只画到某一等：

```
N > 100 → 三等以下退成 22% 底纹
N >  40 → 二等以下退成底纹
放大 1.5× 放宽一档，2.4× 全部还原
```

这是纸质全天图的老办法。暗星退成底纹后与星尘融为一体，视觉上正确。

### 6.5 实测

| n | 可见注记 | 重叠对数 | 标注压住星 |
|---|---|---|---|
| 8 | 3 | **0** | **0** |
| 60 | 6 | **0** | 0 |
| 160 | 3 | **0** | 0 |

## 7. 图层（默认全关）

- **时间尺**：年轮不删，降成版心底部的一把直尺。每颗星垂一根虚线到它**真实的节气**上。

## 10. 三个必踩的坑（原型里全踩过）

1. **`color-mix()` 写在 SVG 的表现属性里不解析**，`fill` 会**静默变纯黑**。只能写进 CSS。
   而且它引用的 var 一旦未定义（当时是丢了 `--star-base`），整条声明在计算值阶段失效，同样变黑。
2. **字号锁屏幕、间距写 viewBox 单位**是这套设计最容易犯的错。相机缩到 0.42 倍时
   所有行距只剩四成：款识挤成一坨、星座名互相叠，而碰撞检测按 viewBox 算出来是「不重叠」的。
   **算得对，看着全叠着。** 凡是与恒定屏幕尺寸的字有关的间距，都要乘 `1 / ctm.a`。
   款识那一整块最后是放进 `scale(calc(1 / var(--s)))` 的子组、内部一律按 px 排版才对的。
3. **注记避让必须在 `fit()` 之后用 `getBBox()` 量真实宽度。** 用「字数 × 猜的字宽」算净空，
   长中文标题（《以史为鉴，不泥于史》）永远算窄。
   量一次拿宽高即可，每个候选位都 `getBBox()` 会触发上千次强制重排。

另外：运行时 `feTurbulence` **只在原型里用**，正式实现必须离线烘成 PNG——那是每帧的 GPU 开销。

不是用来「致敬」的，是每一条设计决定背后真实的依据。

**版面与制图**
- **苏州石刻天文图（1247）/ 敦煌星图** —— 拓片美学（暗底白线），正好是夜间态，而且是中文语境的
- **Urania's Mirror（1824）** —— 星等要**数得出来**；名字用衬线 + 大字距
- **Bayer《Uranometria》/ Hevelius** —— 让天空可记的是**图形**，不是网格
- **原研哉《白》** —— 「白是被边界定义的空」：刻边那条的全部理由
- **杉浦康平** —— 同心多层编码是对的，但他的图都是**稠密**的；这正是年轮盘该等到什么时候才登场
- 制图学的八方位注记择位与优先级（右上优先）—— 6.2 的出处
- WCAG 2.2 **1.4.11 Non-text Contrast**（3:1）—— 墨度换档的硬下限

**水墨**
- **墨分五色**（焦浓重淡清）—— 5.2 里白天星等的做法
- 宣纸迎光的**帘纹**（laid lines）—— 纸纹取的是这个，不是水彩纸的粗颗粒
- **乌丝栏** —— 白天单道版框的出处
- **闲章用朱砂** —— 纸上唯一的第二色

**星空渲染**
- [procedural-stars-threejs](https://github.com/CK42BB/procedural-stars-threejs) ——
  配方是「黑体光谱色（O–M）× 星等 × 亮星才有的衍射芒」。本项目的 `--sky-sp1..5`
  本来就是一条 O–M 光谱阶，只是一直当纯色用了
- [SVG star generator](https://graphmake.com/tools/star-maker) —— sparkle 的内半径要 ~0.15 才够尖
- 天体摄影的老经验：**亮星的色在晕上，核已过曝成白** —— 5.1 里核色反着走的依据

**功能设计**
- [Obsidian graph view 的批评共识](https://medium.com/@ann_p/visualizing-connections-graph-views-in-obsidian-tana-and-anytype-3c767e08fe66)
  —— hairball 问题：连接一切等于不连接；有意义的知识图是**簇内密、簇间疏**。
  这是「砍掉共享标签线」那条的出处
- **中村勇吾 / tha ltd.** —— 动效只在有事发生时出现，不做常驻装饰
- **Nadieh Bremer**（Data Sketches）—— 径向标注避让的现代实践
