# 星图再版方案 v5 · 砂与星，可读的庭院

> 已由 [v5.1 保留质感精修方案](constellation-v5.1-refinement.md) 修订。用户认为本版示意过于简陋，原型质感更好；本版的扁平化视觉、材质删减和功能删除清单不再作为当前推荐方向。可读性与阅读闭环分析仍可参考。

日期：2026-09-26 · 状态：设计提案，未改动生产组件

依据：`sandprototype.html`、`constellation-v4.1-detail-spec.md`，以及现有 `OasisOrchard` / `constellation.ts` 的数据与关系模型。附带交互示意只验证视觉方向、目录与详情切换、昼夜表现，不代表完整功能已经实现。示意中的文章取自原型快照，未重新查询线上数据；窄屏使用上下排列来展示内容，尚未模拟提案中的底部抽屉、相机手势和完整动效时序。

## 1. 设计结论

保留“昼为砂庭，夜为星池”。再版的重点是让人先看到文章，再发现文章之间的联系。庭园气质来自安定的构图、细微材质和少量有因果的动效，不需要每个数据字段都发明一种景物。

建议采用：**一张稳定的地图，一个可切换的侧栏，三种清楚的关系，少量主动发生的美感。**

核心阅读路径：浏览目录或点一块石 → 看标题、摘要、关系 → 打开文章 → 返回原来的位置。愿意探索的人可以继续沿合集走；想直接阅读的人可以完全通过目录完成操作。

这是有意保留个性的减法。白天仍有石的体积、绕石的砂纹；夜间仍有星的光晕；分类题签仍有手写气息。简化的是控制数量、重复信息和同时发生的动作。

## 2. 对初版的判断

### 值得继承

- 昼夜共享几何位置，维护空间记忆。
- 文章真实关系有出处：合集顺序、正文引用、共同话题，而不是随机连线。
- 目录与空间地图互为入口，不强迫访客学会图谱。
- 初音绿、樱粉、中文标题与枯山水的组合，和 Oasis 的整体气质相容。
- 程序化石形可稳定复现，低饱和材质比照片贴图更容易适配缩放和主题。

### 优先修正

| 观察或代码事实 | 体验影响 | 再版决策 |
|---|---|---|
| 1280×720 昼间预览中，目录底部的标签和图例常驻，占去较多高度 | 真正的文章列表只露出少量行，信息入口比装饰拥挤 | 分类与合集放目录；话题进入筛选；图例变为“怎么看”按需打开 |
| 首屏标题是很小的中英 eyebrow，正文标题反而都在侧栏里 | 用户难以迅速理解页面用途 | 给“星图”一个真正的中文标题，配一句功能性说明 |
| 元信息、工具栏与英文大量使用 9–11px 字号和大字距 | 精致感依赖大屏，阅读成本高 | 重要辅助文字至少 12px；正文 14–16px；英文只留页面级一处 |
| 目录与右侧星卡同时出现 | 1280px 宽时，中央可用区域约只剩 520px，再留内边距后更小 | 同一个 304px 侧栏在“目录 / 详情”之间切换 |
| 160 篇夜间预览中，星芒、环、连线和地形轮廓叠加 | 光点彼此竞争，关系难以分辨 | 普通节点静态；只强化当前文章及其直接关系 |
| 石高、五等大小、皴、苔、虚线、十字芒、四角芒都编码内容 | 图例负担高，“长”也容易被看成“好” | 篇幅改成三档弱编码；生长度用文字为准，地图标记简化 |
| “双链为空”的卡片展示 `[[标题]]` 写作教学 | 访客被引导到站主工作流 | 空关系区不显示；编辑提示仅园丁可见 |
| 时间拨盘关闭前自动快进，代码约 520ms + 160ms 后才开始收起 | 一个关闭动作承担了额外叙事 | 首版移除回放；保留低成本的年份筛选 |
| 原型 `NOW` 固定为 2026-09-24 21:40 +10:00 | “今夜”与真实时间不一致 | 首版不承诺实时天文；若保留彩蛋，明确城市、日期、近似性质 |

**检验边界：** 本次实际查看了 1280×720 下的昼间 8 篇、夜间 160 篇及选中文章状态，并读了移动端代码。移动端建议仍需真实尺寸原型验证，不把规格中的截图、对比度或性能宣称当作本次测量结论。

本地文件的字体路径仍保留旧目录深度 `../../node_modules/…`，从现在的 `docs/` 直接打开会指向仓库外；HTTP 服务在站点根路径解析时可以落到 `/node_modules/`。后续原型应改成位置正确的路径，生产版使用现有字体导入。还需整理规格里指向旧原型名称、`img/` 与 `assets/` 的相对引用。

## 3. 网络设计研究：借什么，怎么用

以下是参考后的设计判断，不是这些网站对 Oasis 给出的结论。网站设计与摄影只用于学习，不直接复制成站内素材。

| 来源 | 具体学习点 | 对 Oasis 的应用 |
|---|---|---|
| [NIPPON COLORS](https://nipponcolors.com/)（已查看页面） | 色彩作为统一空间，文字与数据集中组织，留白有方向 | 纸白／青墨构成大底；分类色只做小面积提示；竖排只用于短分类题签，普通操作横排 |
| [Obsidian Graph view](https://obsidian.md/help/plugins/graph)（官方功能说明） | 全局图与当前笔记的局部图承担不同任务 | 全局看分布；点击后显示直接关系。首版只展开一跳，不把全部话题连成网 |
| [Are.na](https://www.are.na/about)（官方介绍） | 用集合组织资料与连接 | 合集必须具有可靠的文字目录；空间小径是辅助入口，不替代目录顺序 |
| [NN/g：渐进披露](https://www.nngroup.com/articles/progressive-disclosure/) | 先呈现高频功能，再按需展开低频内容 | 搜索、目录、阅读常驻；年份、话题、图例和站主管理进入明确的次级入口 |
| [NAJGA：枯山水砂纹](https://najga.org/7-common-raking-patterns-in-japanese-dry-landscape-gardens/) | 砂纹通过流向、波纹及光影表达水 | 保留局部弧线与绕石纹理，减少满屏等距直纹；不把每个分类画成封闭国界 |

专业原则落成三件事：让重要内容具有更强的视觉对比；让点击产生可以预期的局部变化；让同一位置、形状、色彩在不同状态里尽量保持同一含义。

## 4. 功能取舍

| 项目 | 决策 | 规格 |
|---|---|---|
| 分类、合集、文章目录 | 保留并强化 | 默认展开首个含文章的分组；有明确折叠符号与篇数 |
| 搜索 | 保留 | 搜索标题、标签、合集；清楚展示命中数与清除入口 |
| 选中卡片与进入阅读 | 保留 | 标题、日期／时长、短摘要、阅读按钮优先 |
| 合集顺序 | 保留 | 显示“第 3 / 6 篇”和前后篇；长合集使用文字目录 |
| 正文引用与反向引用 | 保留 | 明确“引用了 / 被引用”；只显示与焦点相关的连线 |
| 共同话题 | 简化 | 详情里显示最多 3 篇及共同标签；可展开更多；全图不画两两连线 |
| 平移、缩放、全图 | 保留 | 地图右下角固定三控件；缩放不重排世界坐标 |
| 昼夜主题 | 保留 | 复用全站 auto/light/dark；示意图可独立切换，生产版不另造主题状态 |
| 竖排庭名 | 限定保留 | 桌面宽松且 2–4 字时使用；长分类名和手机横排；取消侧排英文与尾部篇数 |
| 苔、空心种子 | 精简 | 全图最多一个静态状态记号；准确生长度在详情里说明 |
| 灯笼、双栏杆石桥、交错踏石 | 大幅收敛 | 首版统一用低调路径；合集起点用“01”；仅选中小径时可出现少量踏石暗示 |
| 话题包络线、MST 连接 | 首版移除 | 话题匹配用节点高亮与结果列表表达 |
| 时间柱、节气刻度、自动回放 | 延后 | 首版仅年份筛选；手动回放可以作为后续独立彩蛋 |
| 真实星空、月相百分比 | 默认移除 | 保留恢复余地；它们与读文章无直接关系，还会混淆文章星和背景星 |
| 粒子、落叶、萤火、持续照料水纹 | 移除 | 稳态无持续动效；选中时一圈涟漪足够形成记忆点 |
| 待照料 | 保留管理能力，退出访客界面 | 仅园丁的管理入口提供；与访客筛选独立 |
| 规模切换、慢放、样张 | 只属于开发原型 | 不进入生产首屏 |

“移除”是建议的再版范围，本次没有删除原型或任何现有功能。

## 5. 信息架构与布局

### 桌面：地图 + 单侧栏

页面顶栏：左边“星图”与一句说明，右边复用全站主题入口。下方左侧是目录，右侧是地图。底部 Dock 保留全站组件及原顺序。

侧栏默认显示目录；点击文章后，在原侧栏的位置替换成详情。顶部有“返回目录”，保留之前的展开项、搜索词与列表滚动位置。点击地图另一篇时只换详情内容。这个决定牺牲了同时比对完整目录与详情的便利，换回更稳定的地图宽度；常见阅读路径更受益。

| 尺寸 | 布局建议 |
|---|---|
| ≥ 1200px | 外边距 32；侧栏 304；间距 32；地图拿走余下空间 |
| 900–1199px | 外边距 24；侧栏 280；间距 24；题签横排；隐藏装饰英文 |
| 600–899px | 地图为主，目录通过明确的“目录”按钮开启；详情与目录共用一个面板 |
| < 600px | 底部半屏面板，三档高度：收起约 88px、浏览约 42dvh、展开最高 82dvh |

标题区域约 96px 高，但服从全站外壳实际占位。地图底部预留 Dock 的实测高度、16px 间距和安全区；不要复制原型的固定 120px 到所有设备。相机可用区由真实面板边界计算，使用 `ResizeObserver`，不是在多个函数里散落相同常数。

### 手机

首屏显示地图、页面标题、可见的“目录 · 8 篇”面板标题和 2–3 个文章入口；不先铺满半屏标签。点击文章后，面板进入详情状态，标题、时长和“阅读全文”在无需滚动的位置。摘要以 2–3 行为限，关系列表可继续展开。

展开到最高档时允许内容滚动；图谱暂停拾取，防止一边阅读一边误拖背景。面板手柄提供“展开 / 收起”按钮，不能只靠拖拽操作。全站 Dock 作为底层导航，展开的大面板可以遮住它；模态展开态关闭后恢复，不把两套导航挤在卡片底边。

软键盘出现时搜索面板占用可见区域，暂停相机自动移动。横屏低高度和 200% 缩放允许退为全宽列表，保留所有阅读能力。

## 6. 视觉系统

### 颜色：暖纸、青墨、矿物灰

白天减少橙黄光晕与大面积玻璃白；夜间从近黑蓝调整到青墨，仍与全站夜色相接。初音绿保留为品牌原色，小字号与关键图形使用更深或更亮的语义版本。樱粉只提示“新近更新”等少量信息，不再参与每次选中的第二圈动画。

| 用途 | 昼 | 夜 |
|---|---|---|
| 场景底色 | `#FAF8F3` | `#0D171B` |
| 面板底色 | `#F4F2EB` | `#142328` |
| 主文字 | `#293D3A` | `#E4ECE7` |
| 次文字 | `#586965` | `#ABBDB7` |
| 辅助文字 | `#64736F` | `#9BAFA8` |
| 强调文字 | `#176F69` | `#7AD7CB` |
| 选中环／功能线 | `#39847E` | `#5CAFA6` |
| 石的基础色／星的辅助边界 | `#747E78` | `#A1ADA4` |
| 品牌装饰色 | `#39C5BB` | `#39C5BB` |
| 更新提示装饰色 | `#FFB7C5` | `#FFB7C5` |

通过标准 sRGB 相对亮度公式，本次计算了纯色背景上的候选值：昼间主／次／辅助文字分别约 10.85 / 5.46 / 4.68:1，强调文字 5.63:1，选中线 4.14:1；夜间对应值更高。**这不是整个页面通过无障碍检验的声明**：混合透明度、渐变、面板背景及弱化状态还要按实际合成色验证。

分类色继续沿用已有分类数据，避免更换用户对色彩的记忆；只降低用于材质的饱和度。分类名称必须同时存在，不能只靠五种相似灰色辨认类别。

### 文字与间距

| 角色 | 字体与规格 | 使用规则 |
|---|---|---|
| 页面标题 | LXGW WenKai Screen，28–32 / 1.35 | 正常字重，字距约 .04em |
| 分类题签 | WenKai，17–18 / 1.5 | 可竖排；移动端横排 |
| 地图文章标题 | WenKai，14 / 1.5 | 高对比，不随地图缩小字号 |
| 目录行 | 系统中文无衬线，14 / 1.6 | 44px 最小行高，长标题可两行 |
| 详情标题 | WenKai，24 / 1.45 | 最多三行，不用很宽字距 |
| 摘要 | 系统中文无衬线，15 / 1.8 | 正体；取消整段中文斜体 |
| 日期、篇数、阅读分钟 | 系统字体 12–13；数字可 Mono | 不再全用 9px 等宽字体 |
| 英文点题 | EB Garamond，14–16 | 每页最多一处，不重复翻译分类 |

以 4px 为细调单位、8px 为主间距。侧栏内边距 20，标题到正文 12，区块间距 24。文章行用一条细的选中标记与浅底色，不让每一行都变成胶囊。圆角收敛为面板 18、输入框 10、按钮 10；全站 Dock 的外形照旧。

### 背景与材质

- 背景约九成保持安静的底色，仅一处低饱和的光感，不新增四角准星和强暗角。
- 直砂纹仅用于地图局部，屏幕间距 10–14px，建议 4–7% 不透明度；小屏关闭。不要穿过文字区与侧栏。
- 分类簇外围最多两条不闭合的柔和轮廓，约 10–16% 不透明度。它们只负责氛围；分类信息由题签与目录承担。
- 不给每个孤立节点都画三重同心圆。绕石纹理主要服务密集簇的整体构图，避免“细胞标本”观感。
- 夜间保留局部微光，默认没有伪装成数据节点的背景星。若日后恢复天文彩蛋，限定极低对比、无拾取、无连线，并提供关闭入口。
- 面板使用接近实色的纸面／暗面，仅保留细边界和轻阴影。避免多层高模糊玻璃把背景纹理混进文字。

## 7. 节点、关系与密度

### 一眼能懂的图形语法

| 内容 | 视觉表达 | 不承担的含义 |
|---|---|---|
| 文章 | 昼：带细微体积的石；夜：小光核与紧凑光晕 | 亮度不表示“推荐”或文章质量 |
| 篇幅 | 三档弱差异：< 8、8–17、≥ 18 分钟；昼直径约 12 / 16 / 20px | 不要求用户按面积精确读分钟数；时长写在文字里 |
| 分类 | 短题签、目录色标、石的淡色倾向 | 不使用实体围墙分割知识 |
| 合集 | 一条连续细线；聚焦时显示 01 起点与当前章序 | 不把两个相邻石头当作自动成立的合集 |
| 正文引用 | 聚焦时出现的弧形虚线，附“引用了 / 被引用”文字 | 一条引用不是天然双向，不能只叫“双链”就省掉方向 |
| 共同话题 | 文字标签与对应节点高亮 | 不因共享一个宽泛标签就生成满屏强关系 |
| 生长度 | 详情文字；必要时一个小型空心／实心状态记号 | 去掉五等星芒与常青星芒叠加 |

三档门限和尺寸属于设计起始值，需用真实文章分布校准，不宣称实验已证明最优。旧文档关于 Flannery、1.26 倍和“感知等距”的推导不足以直接证明这些小尺寸不规则石形的可辨性；再版不依赖这种精确宣称。

### 关系分层

默认全图只轻画合集骨架，引用线按需显示，共同话题不画线。选中文章后，优先展示同合集前后篇、直接引用及被引用的文章，再展示少量同话题文章。详情中的每项关系都说明原因；无关系时省略空区块。

同一对文章兼有合集和引用时，地图只画一条主关系线，详情列出两种原因。跨分类的合集允许跨区连接，分类边界只作视觉提示，不重复复制节点。文章排序继续与现有阅读舱保持一致；相同时间戳要使用同一稳定的次排序规则。

### 密度与布局稳定性

- 0 篇：明确空态；访客看到“这里还在生长”，园丁才看到写作入口。
- 1–12 篇：尽量显示全部文章标题；不用假节点填满空白。图形主体占地图约 45–60%，避免几粒石头缩在角落。
- 13–60 篇：优先焦点、邻居、合集入口、当前查询命中项；其余标题按屏幕碰撞择位。
- 61–160 篇：全景显示分类和合集入口；缩放后逐步出现文章标题。过密点击区域提供小型候选列表，不悄悄选错最近节点。
- > 160 篇：先测实际密度与帧耗；必要时才加入显式聚合，并显示真实篇数。不要为了预想中的上万篇先引入重型图谱引擎。

采用现有稳定布局作为基线。昼夜、选中、悬停、搜索和过滤均不重新运行布局；删除或回填历史文章的稳定性需要单独定义，不能把“同一输入确定”误认为“任何编辑都不移动”。新内容到来可以出现更新提示，在空闲或用户选择后再纳入布局。

标签采用屏幕坐标布置。可见标题之间留至少 6px；标签位置保持到交互结束，避免拖动时跳来跳去。低密度时列出全部短标题，密集时降低标签数量，绝不把文字缩到不可读。选中标题可有 1.5–2px 底色细描边，避免全图粗白边。

## 8. 核心交互

| 动作 | 即时反馈 | 后续变化 |
|---|---|---|
| 悬停文章 | 本节点轻提亮，显示标题；目录行轻高亮 | 不移动相机、不自动滚目录、不把全图降到 20% |
| 点击文章 | 立即出现选中环 | 侧栏换详情；只有被遮挡时才做最短距离的相机平移 |
| 点击下一篇 | 新节点先标记，详情更新 | 保持面板尺寸，不逐行排队入场 |
| 返回目录 | 恢复原目录滚动位置与展开项 | 保留地图位置；“全图”才负责重新取景 |
| 点分类或合集 | 目录给出明确筛选状态 | 可触发一次取景；后续悬停不再移动 |
| 搜索 | 约 120–180ms 防抖，更新命中数 | 只高亮，不逐字自动飞行；Enter 定位选中的结果 |
| 年份／话题筛选 | 显示可清除的筛选条件 | 文章按条件显示但坐标不变；零结果给出清除筛选 |
| 点击空白 | 取消临时悬停；选中态保持 | 使用明确的关闭或 Esc 退出，避免拖图时误关 |

搜索、分类、话题、年份合并为 AND；同一筛选内若允许多选则明确为 OR。详情展示的关系也遵从可见数据权限。筛选把当前文章排除时，回到结果目录并说明原因，而不是留下无内容的星卡。

URL 与阅读闭环：复用 `#/garden/<postId>` 打开阅读，以及现有 `#/constellation/<postId>` 选中星图文章。已核对当前 `route.ts`：`ITEM_VIEWS` 包含 garden、orchard、atelier，星图单条目路由已有支持，不需要另建路由系统。浏览器返回恢复选择和相机仍要在组件重构时验证；查询词等探索状态只在确有需求时放 URL。无效或已删除 ID 回到目录并给出轻提示。

## 9. 动效：少而连贯，随时可打断

| 场景 | 提案值 | 编排 |
|---|---|---|
| 按钮／悬停 | 120–160ms | 颜色或 1px 位移，移出立即恢复 |
| 目录到详情 | 180–240ms | 整体淡入并位移 6px；无七行错峰 |
| 选中反馈 | 120ms 环显现 + 650–800ms 单圈涟漪 | 一圈初音绿，扩散后停止；连续点击合并或取消旧圈 |
| 相机让位 | 280–420ms | 只平移必要距离；用户拖动立即取消 |
| 全图／跨区定位 | 360–480ms | 平移和适量缩放一起完成，不旋转、不弹跳 |
| 首次进入 | 总体 ≤ 500ms | 文字和控件立即可用；场景轻淡入，不等所有石头逐个落下 |
| 昼夜 | 450–650ms | 几何与标签位置不变；背景双层交叉淡入，石／星替换；保证文字在过渡中可读 |
| 关闭面板 | 140–180ms | 直接收起；不附加快进或其他动作 |

进入使用项目已有 `cubic-bezier(.16,1,.3,1)`；退出约 `cubic-bezier(.4,0,1,1)`。避免为所有场景配置不同弹簧。反馈从第一帧发生，完成动画不能成为执行用户命令的前置条件。

可见稳态不运行持续动画。装饰优先 opacity / transform；复杂 SVG 或 canvas 的性能仍需测量，不能仅凭使用这两个属性就保证流畅。交互期间只更新相机与轻量标记，标签避让和砂纹重建放在结束后。昼夜过渡不要重复创建整棵图，也不让全站背景和场景同时播放两套长转场。

`prefers-reduced-motion` 下关闭扩散、缩放、飞行与错峰，状态直接更新，必要时保留极短淡入。相机仍需把目标置于可用区，但不飞过去。页面不可见时暂停一切装饰任务。

## 10. 可访问性与性能验收

普通正文的对比度至少 4.5:1；必要图形、操作标记至少 3:1。节点是交互入口，不能笼统归入“材质所以豁免”。若使用低对比装饰线，真正表达同一关系的高对比文字必须清楚可见。[W3C 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

触屏采用 44×44 CSS px 的项目目标，并处理重叠命中区域；WCAG 2.2 AA 的 2.5.8 是 24×24 CSS px 或符合相应间距／例外，不能把项目的 44px 说成该条标准的统一要求。[W3C 目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

目录是完整可用的键盘入口。图谱若提供键盘导航，使用一个入口加方向键空间导航，避免 160 个 Tab 停靠点；Enter 选中，Esc 返回上一层。输入框内不截获普通字符快捷键。详情打开、关闭要有明确焦点管理，隐藏面板不留可聚焦元素；移动端模态面板正确圈定焦点。只播报选择与结果数量，不用 live region 朗读每一帧。[W3C 交互动画](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)。

以下都是待实现时验证的目标，不是本次实测成绩：

- 用 8 / 60 / 160 篇，在 1440×900、1280×720、1024×768、390×844、320px 宽及 200% 缩放下检查。
- 160 篇桌面拖动争取 60fps；目标设备上记录帧耗，先减砂纹和光晕，再决定是否更换渲染技术。
- 拖动时不反复执行文章解析、全量布局、DOM 文本测量；无相关操作时停止 requestAnimationFrame。
- 详情首屏可见阅读按钮；30 字标题、自定义长分类名、无合集、跨分类合集、无引用、零搜索结果均不破版。
- 连续点不同文章、拖动中切主题、筛选后返回、文章删除、中文输入法候选、字体延迟加载均有稳定结果。
- 找几位未见过原型的人完成“找到一篇文章并打开”“解释一条连接”“沿合集到下一篇”；记录犹豫点，不先教他们图例。若做不到，继续删隐喻和显式化文案。

## 11. 素材与导入策略

本次实际采用的外部设计语言是低饱和色彩、局部关系聚焦和渐进披露；没有把网站截图、摄影或未经核实的纹理下载进生产目录。下一版优先复用已有字体、站内图标和原创程序化石形，不需要为“有素材”而增加请求与许可负担。

| 资源 | 处理方式 | 许可与记录 |
|---|---|---|
| 现有 WenKai / EB Garamond / JetBrains Mono | 生产版沿用已安装依赖；示意用字体栈，实际可用字体随环境而定 | 发版时随依赖保留相应字体许可；不重打未经验证的超大字体包 |
| 砂纹、石、光晕 | 自绘矢量／CSS；不导入 3D 模型与石头照片 | 与项目同；适合主题与缩放 |
| 图标 | 生产优先站内已有系统；示意使用宿主 Lucide | 若未来导入 Lucide，按 [官方 ISC 许可](https://lucide.dev/license) 保留声明 |
| 纸／砂纹理候选 | 如纯矢量仍显得过于平滑，再从 [ambientCG](https://ambientcg.com/index.php) 选一张 | 官方提供 CC0 资源；具体素材选定后记录原始链接、许可、处理过程；限制为小平铺图，桌面可选 |
| NAJGA 庭园摄影、NIPPON COLORS 页面 | 只作为研究参考 | 不假设网站照片、界面素材可自由再分发 |
| BSC5 星表 | 首版不加载；原型内已有数据不删除 | 若恢复，核对数据文件及转换来源的许可，注明日期／地点；不可只凭“公开数据”推定任意使用许可 |

建议新增素材时维护 `docs/constellation-assets.md`：文件、作者、原链接、许可证、修改方式、字节大小、用途、是否已实际导入。当前没有需要伪造“已导入”状态的新增外部位图。

## 12. 落地顺序与范围

### P0：先完成阅读路径

接入真实 `useGarden` / `useCategories`、单侧栏、文章选择、阅读返回、搜索、空态、手机面板。保留现有 `buildGraph` 的数据意义，把“有哪些关系”与“画哪些关系”分开。发布前确认权限、深链及键盘入口。

### P1：完成场景视觉

加入昼夜语义色、三档石／星、两层砂纹、标签避让、局部关系、单圈涟漪。用真实文章量检查布局，再验证 60 / 160 篇，不以模拟数据替代真实验收。

### P2：有使用反馈后再加

年份筛选、园丁照料入口、超大数据量聚合；真实星空或手动生长回放可独立讨论，均不阻塞核心阅读体验。

组件职责建议仅拆到有独立状态和测试价值的边界：`ConstellationStage`、`ConstellationPanel`、`ArticlePreview`、`useConstellationCamera`；石形、标签避让为纯函数。不要一开始把每一层装饰拆成十几个新模块。配色令牌先限制在星图作用域，全站可读性提升另立范围。

优先测试状态与含义：关系方向、合集顺序、筛选组合、相机取消、返回恢复与无效 ID。材质和像素尺寸主要做视觉验证，不为每条 CSS 写镜像测试。

**完成标准：** 用户无需学习石灯笼、星等和桥的图例，也能找到并打开文章；停下来多看一会儿，才发现砂纹、光晕和文章之间的小径。
