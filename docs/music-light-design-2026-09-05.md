素材制作建议：唱片继续使用现有程序化沟槽和反光；空间光用渐变生成；纸面、磨砂金属的质感通过少量静态明暗体现。首轮不需要新增大图或循环视频。以后若加入专辑封面，将其放入唱片中央标签或碟套，优先利用曲目已经整理好的素材。同一空间中保留统一的左上方材质反光方向；唱片旋转时纹理转动，环境照明保持稳定。

**3．空间与阅读层级**

桌面继续采用演示中的真实两列布局：左侧唱片和曲目信息，右侧选碟、歌词、待播。两区共享背景，播放控制横贯下方。光晕固定在内容舞台内部，底部控制条有稳定底色。

手机保留唱片、歌词、选碟三个面板及常驻控制。唱片视图显示主光；歌词视图将气氛收成当前句背后的弱光；选碟视图只保留静态色调。短屏先压缩唱片和留白，保证歌名、进度条、播放键不重叠。

视觉阅读顺序：唱片与歌名 → 当前歌词或所选曲目 → 播放控制 → 环境光。背景即使达到峰值，也不应把视线从歌词上拉走。

**4．两处光区，三种职责**

唱片附近分为近光和远光；歌词区只有阅读衬光。实现层可以分开，观感上仍应是一束光照进同一个空间。

| 层次 | 形态与位置 | 响应 | 首轮参数 |
| --- | --- | --- | --- |
| 唱片近光 | 唱片背后的松散椭圆，中心略偏上；圆盘遮住中心，只露出边缘柔光，边缘没有清晰描线。 | 低频与瞬态影响亮度，尺寸轻微变化。 | 光层外框约为唱片直径的 1.35–1.55 倍；scale 1.00–1.035。 |
| 空间远光 | 更宽、更淡、近似静止的色雾，从唱片向两列之间铺开，在歌词正文前衰减。 | 只跟随音乐较慢的整体起伏。 | 宽约唱片直径的 1.8–2.2 倍；默认只改变 opacity。 |
| 歌词衬光 | 当前句背后的宽椭圆，与排版焦点一致；多行歌词也不能变成一条窄亮线。 | 由当前句状态控制显隐，音乐仅提供极弱调制。 | 可用行宽的 75–90%；高度覆盖当前句及译文附近；scale 默认固定。 |

光层外框包含透明边缘，不是均匀可见的实色面积。具体亮度必须按渐变自身 alpha × 元素 opacity × 最终底色的合成效果检查，不能把某一个 opacity 数字当成最终光强。

日间近光元素 opacity 可先试 0.08–0.16，夜间 0.12–0.24；远光约为近光视觉强度的三分之一；歌词衬光低于近光。以上以中心颜色不透明、边缘透明的基础渐变为试调口径，之后按实际层叠校准。

选择歌词后，桌面唱片光的调制幅度降到唱片视图的约 60%，歌词保持稳定。用户手动翻词时，衬光淡到基础值，避免照亮与实际播放脱节的句子；点击“回到此刻”后随当前句恢复。

**5．颜色与日夜材质**

品牌初音绿继续负责站点身份。当前曲目的色彩负责局部情绪，两者各有位置。现有 Track.color 已可作为主色，第一版按专辑归一化、必要时单曲覆盖；先保留人工整理能力。

| 色调试作 | 光色种子 | 搭配背景 | 用途 |
| --- | --- | --- | --- |
| 青绿 | #39C5BB | 暖白、墨青 | Oasis 的默认音乐气氛 |
| 雾蓝 | #8DAFC3 | 纸白、深蓝灰 | 夜色、雨景方向的专辑试样 |
| 樱粉 | #DCA5B7 | 暖灰白、深灰紫 | 柔和色调的专辑试样 |
| 浅琥珀 | #D6B57C | 米白、深褐灰 | 暖色专辑试样 |

这些命名是美术方向，不是“某种颜色必然对应某种情绪”的心理学结论；不按艺人机械分配固定颜色。

日间基础背景可从 #F7F5F0 起调，让光像纸面上的淡染色；夜间从 #11191B 起调，让光像暗处的柔和反射。夜间增加层次主要靠背景与近光的距离，避免单纯提高饱和度。唱片保持深色实体感，文字保持清楚。

色彩按用途拆分为 moodGlow、accentInk、controlFill，文字色独立验证。歌词和次要文字对合成后的背景按至少 4.5:1 设计；大字最低要求可为 3:1，不能因为是“次要信息”就无限降低透明度。依据：[WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

**6．音乐如何驱动光**

现有 low / mid / beat 足够制作第一版。需要明确：频段包含多个乐器，mid 不是人声识别；瞬态检测也不是准确鼓点识别。getByteFrequencyData 返回的是映射到 0–255 的频谱分贝数据，平均值适合现有装饰信号，不能直接称为真实响度或线性能量。[MDN 频谱数据说明](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getByteFrequencyData)

首轮建议映射：

- 近光目标值：clamp(0.65 × low + 0.20 × mid + 0.15 × beat, 0, 1)。只在亮度上体现大部分变化，缩放严格限幅。
- 远光目标值：对 0.7 × low + 0.3 × mid 做较慢跟随；弱化短促瞬态。
- 歌词衬光：歌词时间轴决定当前句是否存在，句内基本稳定。没有可靠逐词时间戳时用整句强调；纯器乐、间奏与缺失歌词使用各自状态。
- 连续弱音仍有微弱空间底色；静音、暂停和长时间无信号时回归底色，防止为了“始终在动”而放大噪声。

近光视觉滤波时间常数先试上升 60–100ms、回落 450–700ms；远光试上升 400–700ms、回落 1.2–1.8s。这是滤波时间常数，不是动画完成时长；达到约 95% 目标通常需要约三个时间常数。现有频谱平滑会叠加响应延迟，试作时必须测量整体效果，避免多重平滑使声音和光脱节。

平滑继续采用 dt 相关的指数跟随：alpha = 1 - exp(-dt / tau)，不使用“每帧固定加 0.05”之类参数。首先校准安静钢琴、持续人声与密集鼓点三种片段；如果某些曲目长时间顶满，再加入缓慢、有限度的范围适配。

音量滑块不直接乘入装饰强度，避免小音量听歌时画面失去层次；显式静音或音量为零时降低到静态底色。这里只处理应用可知的音量状态，系统音量不作为可观测条件。

**7．关键动作的时间编排**

| 触发 | 用户看到的变化 | 时长起点 |
| --- | --- | --- |
| 进入页面，尚未播放 | 唱片与文字完整呈现；底色已经存在。 | 内容淡入 240–320ms；减少动态时立即显示。 |
| 点击播放 | 点击反馈立即出现；音频实际开始后落针、启转，主光渐起。 | 点击反馈约 100ms；唱针 450–600ms；光入场 600–900ms；唱片约 1–1.6s 建立稳定观感。 |
| 暂停 | 控制状态立即响应，音乐按播放器约定暂停；光逐渐退到底色，唱片滑停。 | 近光 700–1000ms；远光 1.2–1.6s；旋转约 1–1.6s 收尾。 |
| 切歌 | 新曲目名称和加载状态立即更新，空间逐渐换色。 | 文字 180–240ms；光色 1.2–1.6s。相同色系不制造额外闪动。 |
| 选碟切到歌词 | 固定控制条不动，歌词进入阅读区，唱片起伏收弱。 | 面板 240–320ms，位移 8–12px；光的主次调整约 400ms。 |
| 当前歌词换行 | 前后句保持连续位置关系，衬光轻柔承接当前句。 | 280–420ms，短句按间隔缩短；翻译不额外跳一次。 |
| 拖进度 / 快速切歌 | 交互持续跟手，动画接收最新目标。 | 不等待前一动画完成再允许操作；装饰允许短暂滞后。 |
| 缓冲 / 播放失败 | 显示真实状态，音乐调制退到底色。 | 缓冲不模拟强节拍；错误用可读提示和重试操作表达。 |
| 日夜切换 | 背景与文字一起切到正确主题，再让局部光场收敛。 | 基础主题即时切换；光场约 300–500ms 调整，检查过程中对比度。 |

播放动作不能被落针动画延迟。视觉播放状态以实际媒体状态为依据，缓冲与错误应有显式状态。频谱不决定唱片转速：稳定播放时唱片匀速，音乐变化由光表现。

切歌换色使用固定的新旧光层做 opacity 交叉过渡。当前 background-image 的 transition 不能保证渐变平滑换色，因为该属性的动画类型是离散变化。[MDN background-image](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/background-image)

连续切歌只保留最新待切光色；若正在过渡，缩短当前收尾至约 150ms，再转向最新色，不能累计几十个光层或排队回放所有旧颜色。曲目信息和音频选择始终立即追随用户。

**8．性能、可访问性与降级**

| 场景 | 策略 |
| --- | --- |
| 桌面常规播放 | 唱片近光、远光、按需歌词衬光；共用一个视觉时钟和采样结果。 |
| 手机唱片页 | 一个主光层；取消远光；保留小幅 opacity 变化，缩放可进一步降至 2%。 |
| 手机歌词页 | 当前句静态弱衬光；换句短淡变，保持阅读稳定。 |
| 减少动态 | 光色静态，关闭装饰旋转、位移和循环律动；用图标、文案和进度传达状态。 |
| “动态氛围”关闭 | 音乐继续播放，光和唱片装饰保持静态；偏好记住，不干扰下一次进入。 |
| 页面隐藏 / 视图离场 | 停掉对应装饰更新，保留音频与必要播放器逻辑。 |
| 暂停收尾结束 | 取消该区域视觉订阅；全局 ticker 是否停机由剩余消费者决定。 |
| 频谱不可用 | 降级为静态曲目色，不模拟与音频无关的节拍。 |

光效只更新 opacity / transform，渐变形状保持静态；避免每帧重画大面积 blur、box-shadow 或 text-shadow。will-change 按需使用，不向所有元素无差别添加。即使属性适合合成，也要约束覆盖面积与层数，实际流畅度仍需真机测量。[web.dev 动画性能指南](https://web.dev/articles/animations-guide)

“动态氛围”开关放在播放器外观设置中，默认跟随系统减少动态偏好。它让用户可以保持音乐播放，同时停止持续装饰；相关原则见 [WCAG Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)，具体条款适用性取决于自动开始等条件，本提案采用更直接的产品控制。

**9．接入现有代码的顺序**

1. 先在已认可的演示中补主光、歌词弱光、暂停回落和切歌换色；用三组模拟信号说明变化，明确标注为模拟。
2. 风格确定后，提取 ResonanceLight 控制器，收拢旧 DiscHalo / AmbientGlow / StageGlow 的职责。保留原有单例 audio、频谱分析、全局 ticker 与曲库路径。
3. 将播放状态、曲目色、主题、当前面板和减少动态偏好作为低频输入；每帧数据通过 ref / MotionValue 传递，不驱动整个曲库重渲染。
4. 接真实音频校准响应，再同步收敛歌名、歌词、频谱、播放按钮的视觉强度。每个画面只留一个明显承担音乐律动的区域。

首轮必须呈现的内容是：唱片主光、真实的强弱关系、歌词阅读优先、日夜差异、播放/暂停/换曲衔接。粒子、复杂水面焦散、全屏流体与逐曲视频素材暂不进入这轮试作。

**10．效果验收**

- 静止截图：关闭全部装饰动画后，唱片、标题、歌词和控制仍形成完整构图。
- 阅读：在光的峰值与换色中间帧，歌词和次要文字都清楚；长句、双语、无歌词、纯器乐分别检查。
- 连续性：连续快速切歌、播放中拖进度、暂停立刻恢复，均无突然变白、重置旋转角度或旧色依次回放。
- 音乐感：安静钢琴有余光，鼓点片段有可感知但小幅的起伏，持续音不会让背景长时间顶满；静默时不自动假跳。
- 响应：按钮与进度拖动不等待装饰完成；媒体失败不显示“正在正常演奏”的强反馈。
- 设备：检查 1280×720、390×844、375×667 和 320px 宽度，外加至少一台实际手机；记录动画开启与关闭时的帧耗时和长任务差异。
- 实现：稳定播放过程中，光晕本身不引起持续布局或大面积重绘；连续切歌后图层数回到固定预算；后台和暂停收尾后无该区域持续工作。

本轮完成的是研究与设计规格，尚未修改应用代码或上一版演示。后续试作最值得比较的是：近光是否足够柔、夜间亮度是否舒适、歌词出现后注意力能否自然转到文字。
